# i18n Design

**Date:** 2026-06-07
**Status:** Approved

---

## Goal

Let admins choose a default language per game, and let players override the language for themselves. The player-facing UI renders in the chosen language. Six languages are supported at launch: English (en), Swedish (sv), Norwegian (no), Danish (da), German (de), French (fr). Built-in mission names and descriptions are pre-translated; custom (admin-created) missions are translated on first view and cached.

## Scope

This feature touches:
- A Supabase migration (one new column on `games`, one new table `mission_translations`)
- One new utility (`lib/i18n.ts` — react-i18next instance setup)
- One new component (`components/LanguagePicker.tsx` — player language selector)
- Translation JSON files (`messages/{locale}.json` + `messages/missions/{locale}.json`)
- One new shared utility (`lib/translate.ts` — Google Translate wrapper for custom missions)
- One modified API route (`POST /api/team/login` — triggers custom mission translation when game language ≠ 'en')
- One modified admin API route (`POST /api/admin/game` — accept `language` field)
- UI changes in `AdminScreen.tsx` (language dropdown in create-game form)
- UI changes in `MissionsScreen.tsx` and `LoginScreen.tsx` and `ChallengeScreen.tsx` and `TeamPowerupsScreen.tsx` (wrap all user-facing strings with `t()`)

## Data Model

### New column via migration

```sql
-- games table
alter table public.games
  add column if not exists language text not null default 'en';
```

Valid values: `'en'`, `'sv'`, `'no'`, `'da'`, `'de'`, `'fr'`.

### New table via migration

```sql
create table if not exists public.mission_translations (
  id          uuid primary key default gen_random_uuid(),
  mission_id  uuid not null references public.custom_missions(id) on delete cascade,
  language    text not null,
  name        text not null,
  "desc"      text,
  created_at  timestamptz not null default now(),
  unique(mission_id, language)
);
```

- Stores translated `name` and `desc` for custom missions.
- English is always the source language; the English text lives in `custom_missions` itself — no row needed in this table for `language = 'en'`.
- A row is created on first view in that language (see API section).

## react-i18next Setup

### Installation

```
npm install react-i18next i18next
```

### `lib/i18n.ts`

```typescript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

// Dynamically load locale JSON at runtime (client-side)
export async function initI18n(language: string) {
  const [ui, missions] = await Promise.all([
    import(`@/messages/${language}.json`).catch(() => import('@/messages/en.json')),
    import(`@/messages/missions/${language}.json`).catch(() => import('@/messages/missions/en.json')),
  ]);

  if (!i18n.isInitialized) {
    await i18n.use(initReactI18next).init({
      lng: language,
      fallbackLng: 'en',
      resources: {
        [language]: { translation: ui.default, missions: missions.default },
        en: { translation: ui.default, missions: missions.default }, // fallback
      },
      interpolation: { escapeValue: false },
    });
  } else {
    i18n.addResourceBundle(language, 'translation', ui.default, true, true);
    i18n.addResourceBundle(language, 'missions', missions.default, true, true);
    await i18n.changeLanguage(language);
  }
}

export default i18n;
```

### Language resolution at login

When a team logs in (`LoginScreen` calls `/api/team/login`), the response includes `game.language`. The login handler calls:

```typescript
const savedLang = localStorage.getItem('gameon_lang');
const lang = savedLang ?? game.language ?? 'en';
await initI18n(lang);
```

Resolution order:
1. `localStorage.getItem('gameon_lang')` — player override
2. `game.language` — admin-set default
3. `'en'` — hardcoded fallback

### Language picker

`LanguagePicker` is a small component rendered in `MissionsScreen` (top-right area next to the team/game header). It shows a globe icon that opens a bottom-sheet overlay with 6 language options.

On selection:
```typescript
localStorage.setItem('gameon_lang', selectedLang);
await initI18n(selectedLang);  // updates i18n and triggers re-render via useTranslation()
```

No page reload. All translated strings re-render immediately via `useTranslation()`.

### Using translations in components

```typescript
import { useTranslation } from 'react-i18next';

function LoginScreen() {
  const { t } = useTranslation();
  // ...
  return <input placeholder={t('login.teamNamePlaceholder')} />;
}
```

For missions namespace:
```typescript
const { t } = useTranslation('missions');
const missionName = t(`${mission.id}.name`, { defaultValue: mission.name });
```

## Custom Mission Translation

### `lib/translate.ts` — `translateMission` helper

Called server-side within the team login route when a custom mission is needed in a language with no cached translation.

**Signature:**
```typescript
export async function translateMission(
  missionId: string,
  language: string,
  sourceName: string,
  sourceDesc: string,
  supabase: SupabaseClient
): Promise<{ name: string; desc: string }>
```

**Logic:**
1. Check `mission_translations` for `(missionId, language)` — return cached row if found.
2. Call Google Translate API with `target = language`, `source = 'en'`, for both `name` and `desc`.
3. Insert row into `mission_translations`.
4. Return `{ name, desc }`.
5. On any failure: return `{ name: sourceName, desc: sourceDesc }` (English fallback, silent).

**Environment variable required:** `GOOGLE_TRANSLATE_API_KEY`

### Integration in `POST /api/team/login`

After fetching `customMissions`, if `game.language !== 'en'`, for each custom mission that lacks a cached translation:

```typescript
const translations = await Promise.all(
  customMissions.map(async (m) => {
    const { data: cached } = await supabase
      .from('mission_translations')
      .select('name, desc')
      .eq('mission_id', m.id)
      .eq('language', game.language)
      .single();

    if (cached) return { ...m, name: cached.name, desc: cached.desc ?? m.desc };

    // Translate and cache
    const translated = await translateMission(m.id, game.language, m.name, m.desc, supabase);
    return { ...m, name: translated.name, desc: translated.desc ?? m.desc };
  })
);
```

The `translateMission` helper calls the Google Translate API and inserts the result into `mission_translations`. It is imported from `lib/translate.ts`.

If the translation call fails (network error, API key missing), the original English text is returned — no error surfaced to the player.

### `lib/translate.ts`

```typescript
export async function translateText(text: string, targetLang: string): Promise<string> {
  const apiKey = process.env.GOOGLE_TRANSLATE_API_KEY;
  if (!apiKey) return text; // graceful fallback

  const res = await fetch(
    `https://translation.googleapis.com/language/translate/v2?key=${apiKey}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ q: text, target: targetLang, source: 'en', format: 'text' }),
    }
  );
  const json = await res.json();
  return json?.data?.translations?.[0]?.translatedText ?? text;
}
```

## Translation File Generation Script

A one-time script `scripts/generate-translations.ts` (not part of the runtime app) runs during implementation to produce all non-English JSON files. It:

1. Reads `messages/en.json` (UI strings)
2. Reads `messages/missions/en.json` (mission strings)
3. Calls Google Translate API for each of sv, no, da, de, fr
4. Writes output to the appropriate files

The script is committed alongside the generated files. The generated files are edited by hand if corrections are needed after review.

## Out of Scope

- Admin dashboard translation (AdminScreen strings stay in English)
- Per-mission language override (language is per-game, not per-mission)
- Right-to-left (RTL) language support
- Automatic language detection from browser `Accept-Language` header
- Plural forms beyond simple count interpolation (`{{count}}`)
- Translation of game-event notifications pushed via Supabase realtime (they use pre-translated string keys sent by the server)
- Retroactive translation of already-cached custom mission translations when a new language is added
